# DB Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dựng tầng data Room 3 cho 6 bảng P1 (`accounts`, `categories`, `transactions`, `tags`, `transaction_tag_cross_ref`, `account_balance_snapshots`), có `FinoteDatabase` qua Hilt, DB chưa mã hóa.

**Architecture:** Enum ở `domain/<f>/model`. Entity và DAO ở `data/<f>`. `data/FinoteDatabase` version 1, export schema. `di/DatabaseModule` dùng `AndroidSQLiteDriver`; nhánh `db-encryption` chỉ đổi driver. Test DAO chạy Robolectric, DB in-memory, trong `testDebugUnitTest`.

**Tech Stack:** Room 3.0.3 (`androidx.room3`, KSP), `androidx.sqlite:sqlite-framework`, Hilt 2.60.1, Robolectric 4.17, kotlinx-coroutines-test 1.10.2, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-03-db-schema-design.md`

## Global Constraints

- Version chỉ khai báo trong `gradle/libs.versions.toml`. Không hardcode trong `build.gradle.kts`.
- Tiền là `Long`. Không `Double`/`Float` cho tiền.
- id là `String` UUID. Thời gian là `Long` epoch millis. `monthYear` là `"YYYY-MM"`.
- Một public class/enum mỗi file. File ≤ 300 dòng, hàm ≤ 40 dòng, ≤ 6 tham số (entity constructor là class, không phải hàm; nếu detekt báo thì dừng và hỏi).
- Không `@Suppress`, không baseline, không `--no-verify`.
- `@Insert` giữ mặc định `ABORT`. Không `REPLACE`, không `@Upsert`.
- DAO của 4 bảng có xóa mềm không có hàm xóa cứng. Test xóa cứng bằng SQL thô.
- Hàm `Flow` tên `observeX`, đọc một lần `suspend` tên `getX`.
- Fixture dùng tên, số tiền giả.
- Gradle chạy qua skill `gradle-run`, wrapper `.\gradlew.bat` (PowerShell) hoặc `'.\gradlew.bat'` (Bash).
- `coder` không chạy `git commit`, `merge`. Main session commit, mỗi commit cần user cho phép. Không ghi `Co-Authored-By`.
- Nhánh `feature/db-schema` từ `dev`. `reviewer` chạy một lần trước squash.

## Review Focus

1. Thẻ tín dụng số dư âm và số lớn: `currentBalance = -5_000_000_000` đọc lại đúng, không tràn. Test: Task 2 `account round-trips every column`.
2. Tên tiếng Việt có dấu (`"Ăn uống"`) đọc lại nguyên vẹn. Test: Task 3 `category round-trips every column`.
3. Hai giao dịch cùng `timestamp`: thứ tự phải cố định. `ORDER BY timestamp DESC, createdAt DESC`. Test: Task 4 `observeTransactions orders by timestamp then createdAt`.
4. Hai tài khoản cùng tháng: unique là `(accountId, monthYear)`, không phải `monthYear`. Test: Task 2 `snapshots of two accounts share a month`.
5. TRANSFER có `toAccountId` không tồn tại phải bị chặn. Test: Task 4 `insert with unknown toAccountId fails`.

### Task 2: Account đủ hàm và snapshot

**Files:**
- Modify: `data/account/AccountDao.kt`, `data/FinoteDatabase.kt`, test `Fixtures.kt`
- Create: `data/account/AccountBalanceSnapshotEntity.kt`, `AccountBalanceSnapshotDao.kt`
- Test: `AccountDaoTest.kt`, `AccountBalanceSnapshotDaoTest.kt`

**Interfaces:**
- Consumes: `InMemoryDatabaseRule`, `account(...)` từ Task 1.
- Produces:
  - `AccountDao`: thêm `suspend fun update(account: AccountEntity)`, `fun observeAccounts(): Flow<List<AccountEntity>>` (`deletedAt IS NULL ORDER BY sortOrder ASC, createdAt ASC`).
  - `AccountBalanceSnapshotEntity` (`account_balance_snapshots`): cột spec 3.9 (mục 3.6 spec thiết kế). FK `accountId` → `accounts.id` `CASCADE`. Unique index `(accountId, monthYear)`.
  - `AccountBalanceSnapshotDao`: `insert`, `update`, `getById`, `fun observeByAccount(accountId: String): Flow<List<AccountBalanceSnapshotEntity>>` (`ORDER BY monthYear ASC`).
  - `FinoteDatabase.accountBalanceSnapshotDao()`.
  - Fixture `snapshot(id, accountId, monthYear = "2026-11", ...)`.

- [ ] **Step 1: Viết test**

`AccountDaoTest`:
- `account round-trips every column`: `currentBalance = -5_000_000_000`, `initialBalance = 0`, `deletedAt = null`, mọi Boolean `true`. `assertEquals(account, dao.getById(id))`.
- `update changes the stored row`.
- `observeAccounts hides soft-deleted rows but getById returns them`: ba account, một có `deletedAt = 1L`. `observeAccounts().first()` có hai id, đúng thứ tự `sortOrder`. `getById` của dòng xóa mềm khác null.

`AccountBalanceSnapshotDaoTest`:
- `snapshot round-trips every column`.
- `duplicate account and month fails`: insert hai snapshot cùng `accountId`, `monthYear`, khác id. Lần hai: `runCatching { ... }.exceptionOrNull()?.message` chứa `"UNIQUE constraint failed"`.
- `snapshots of two accounts share a month`: hai account, cùng `monthYear`. Cả hai insert thành công.
- `hard-deleting an account removes its snapshots`: `rule.execSql("DELETE FROM accounts WHERE id = 'acc-1'")`, rồi `getById(snapshotId) == null`.
- `observeByAccount orders by month`: insert `"2026-12"` rồi `"2026-10"`. Kết quả theo thứ tự `2026-10`, `2026-12`.

So khớp lỗi theo message SQLite, không theo class exception, vì class phụ thuộc driver.

- [ ] **Step 2: Chạy, thấy FAIL** — `testDebugUnitTest --tests '*data.account*'`.
- [ ] **Step 3: Viết entity, DAO, fixture, thêm vào `FinoteDatabase`.**
- [ ] **Step 4: Chạy, thấy PASS.** Test FK CASCADE pass chứng tỏ `PRAGMA foreign_keys` đã bật. Nếu FAIL vì xóa không lan, bật pragma qua callback mở kết nối trong cả `DatabaseModule` (Task 5) và rule, rồi ghi vào spec mục 9.

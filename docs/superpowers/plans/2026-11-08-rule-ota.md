# Rule OTA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user opt in to downloading signed parser rules from GitHub, merge them without touching user rules, re-run capture on `FAILED` rows, and move parsing off the main thread.

**Architecture:**
- `domain` gains:
  - a pure `classifyNotification`, shared by capture and re-parse
  - two use cases, `UpdateParserRulesUseCase` and `ReparseFailedLogsUseCase`
  - interfaces for the feed, the rules, the settings and the scheduler
- `data` gains:
  - the feed codec (envelope, ECDSA, checks)
  - `HttpParserRuleFeed`, the only network code
  - the rule and settings repositories
- `work` gains the worker and the WorkManager scheduler.
- `ui/settings` gains a Settings root and a capture settings page.

**Tech Stack:** Kotlin, Room 3, Hilt, WorkManager + `androidx.hilt:hilt-work`, kotlinx-serialization, `java.security` (`SHA256withECDSA`), Compose Material 3, JUnit4, Robolectric, Turbine, Konsist.

**Spec:** `docs/superpowers/specs/2026-11-08-rule-ota-design.md`

## Global Constraints

- **Branch:** `feature/rule-ota` from `dev`. The main session commits, after user approval. `coder` never commits (`git_guard` blocks it). No AI attribution in commit messages.
- **Layers** (`docs/architecture.md`):
  - `domain` has no `android.*`, `androidx.*`, Room or Hilt.
  - `work` depends on `domain` only.
  - `ui` depends on `domain` only.
  - Workers live in `work/`, not `automation/`.
- **Naming:**
  - Use cases expose one `operator fun invoke`.
  - A `Flow` function is named `observeX`.
  - Booleans start with `is`, `has` or `should`.
  - `*Repository` is an interface in `domain/<f>/repository`.
- **Logging:** no `android.util.Log`, no `println`. Never log notification text, balances, account numbers or rule content.
- **Money** is `Long`.
- **Dependencies:** new ones only through `gradle/libs.versions.toml`, no version in `build.gradle.kts`.
- **Strings:** every new string goes in all four files: `values`, `values-en`, `values-ja`, `values-zh-rCN`.
- **Feed URL:** `https://raw.githubusercontent.com/Toanhp123/Finote/main/rules/v1/feed.json`.
- **Network:**
  - `User-Agent: Finote`, no query string, no body.
  - Connect and read timeouts are 10 000 ms each.
  - The body cap is `256 * 1024` bytes.
- **Feed format:**
  - `schemaVersion` is `1`.
  - The signature algorithm is `SHA256withECDSA` on curve P-256. The public key is a base64 X.509 constant.
- **Work names:** `rule-update-periodic` (24 h, `NetworkType.CONNECTED`, `ExistingPeriodicWorkPolicy.KEEP`) and `rule-update-now` (no constraint, `ExistingWorkPolicy.KEEP`). Input key: `isManual`.
- **Regex safety budget:** 50 ms per rule per adversarial input, on the JVM.
- **Verification:** run `testDebugUnitTest` through the `gradle-run` skill after every logic task. Run `qualityGate` before the branch review.

## Review Focus

1. **Crash after merge, before re-parse.** The next run must still re-parse even though it writes 0 rules. Test: Task 6, `reparse runs when nothing was written`.
2. **The feed adds a package the APK never seeded.** Capture must track it from then on, and the bank list must show it. Tests: Task 6, `new package rules are written`, and Task 10, `summarizeBanks lists a feed-only package`.
3. **Status changes during re-parse.** If a row stops being `FAILED` while the re-parse runs (P2c, or a duplicate capture), the re-parse must not overwrite it. Test: Task 5, `updateFailedOutcome ignores a row that is no longer FAILED`.
4. **Fast toggling on, off, on.** The scheduler must end with the periodic work enqueued, and the pref must be `true`. Test: Task 10, `last toggle wins`.
5. **The phone goes offline right after "Check now".** The result must say `NETWORK` and the spinner must stop, not wait forever. Test: Task 8, `manual run without network fails and records NETWORK`.

Not testable on the JVM: an ICU-native regex hang on a device. It is mitigated by Task 2 and noted with a `shortcut:` comment in Task 1.

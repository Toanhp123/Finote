# Account Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user create, edit, star, group, reorder, archive and delete accounts, link masked numbers, and get merge suggestions (roadmap step 14, debts N-10, N-22).

**Architecture:** New writes go through `AccountRepository` methods and new use cases in `domain/account/usecase`, each wrapping its work in one `tx.write`. A new feature package `ui/settings/accountedit` holds the create/edit screen (route `EditAccount(id?, mergeTargetId?)`); merge and ignore dialogs move there. The existing `ui/settings/accounts` list is reworked into grouped list, archive section, merge-suggestion markers and a drag-and-drop reorder mode.

**Tech Stack:** Kotlin, Compose Material 3, Room 3 (SQLCipher), Hilt, Navigation3, JUnit + Robolectric + Turbine, `sh.calvin.reorderable:reorderable` 3.1.0 (new).

**Spec:** `docs/superpowers/specs/2026-11-24-account-manage-design.md`

## Global Constraints

- Branch `feature/account-manage` from `dev`. Commit scopes allowed: `db`, `balance`, `ui`, `build`, or none (`docs:`); never `account`. No AI attribution in commits.
- Money is `Long` VND. Every balance or snapshot change runs inside one write transaction.
- Soft delete for accounts. `account_identifiers` rows are hard-deleted on removal (spec, "Removing a masked number").
- No balance, mask, account number or raw `SQLiteConstraintException` message in Logcat; `toString()` of new types omits them.
- Dependencies only through `gradle/libs.versions.toml`.
- Layers, naming and limits: `docs/architecture.md` (400 lines per file, 60 per function, 80 per `@Composable`, 120 per `*Screen`). Dialogs and sheets in their own file under the feature's `component/`. UI tokens: `docs/design-system.md`. Balances only through `MoneyText`.
- Strings in `values` (en), `values-vi`, `values-zh-rCN`, `values-ja`; zh and ja may be machine-written (N-16).
- `CREDIT_CARD` is not offered on create. Currency stays "VND".
- Gradle runs through the `gradle-run` skill: `'.\gradlew.bat' testDebugUnitTest --tests "<pattern>"`; before the squash, `'.\gradlew.bat' qualityGate`.
- Skills for implementers: `ponytail:ponytail` always; `compose-state-and-effects` for UI tasks; `kotlin-concurrency-and-flow` for flows; `testing-coroutines-with-runtest`, `testing-flows-with-turbine`, `using-robolectric-correctly` for tests.

## Review Focus

1. A provisional account (`isInitialized = false`) that is only renamed or recolored must stay provisional. Test: Task 3, `save without a start change keeps a provisional account provisional`.
2. A notification that changes the account while the user types must not wipe the draft. Test: Task 7, `live update keeps the typed name`.
3. The account is merged or deleted elsewhere while its edit screen is open: the screen closes and says why, Save cannot write. Test: Task 7, `account gone closes the screen`.
4. Masks with a leading zero (`0042`) are kept as typed; `123`, `12a4`, `12345` are refused. Test: Task 4, `mask keeps leading zeros` and `mask must be four digits`.
5. The primary account is archived, ignored or merged away: the star is cleared or moved, and cash entry falls back to last used. Tests: Task 2, `archiving the primary clears the star`, `merge moves the star to the target`; Task 6, `archived primary is skipped`.

# Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Budget tab lets the user set a monthly total budget and budgets for top-level Expense categories that repeat every month, roll over when asked, and raise one system notification at the threshold and one at 100%.

**Architecture:** Two new tables (`budgets`, `budget_months`), migration 13 → 14. A pure `BudgetMath` in `domain/budget/service` turns budget rows and `MonthReport`s (N6, unchanged rules) into statuses, carries and alert marks. Use cases copy a month forward, save, delete, observe, and check alerts. A watcher in `work/` listens to Room's `InvalidationTracker` and runs the check; an Android adapter in `ui` posts the notification (N7). Two new UI features: `ui/budget` (tab) and `ui/budgetedit` (sheet).

**Tech Stack:** Kotlin, Room 3 (SQLCipher), Hilt, Compose M3, Navigation3, `NotificationCompat`, JUnit4 + Robolectric, Turbine, Konsist, AGP screenshot tests.

**Spec:** `docs/superpowers/specs/2026-11-27-budget-design.md`

## Global Constraints

- **Precondition:** `feature/dashboard` is squashed into `dev` (needs the user's approval). Branch `feature/budget` from `dev` (`docs/git-workflow.md`). Commit scopes only: `parser`, `dedup`, `pairing`, `balance`, `db`, `notif`, `ui`, `ota`, `build`, or none (`docs:`). No AI attribution. `coder` never commits; the main session commits each reviewed task.
- Money is `Long` VND. Every sum uses `Math.addExact` / `subtractExact` / `multiplyExact`. No `Double`/`Float` on a money name.
- Budget rows and `budget_months` rows are hard-deleted / never deleted as the spec says ("Delete"); no `deletedAt` column. Every other table keeps soft delete.
- Every write goes through `TransactionRunner.write` (use cases) or `db.storageWrite` (repositories), one transaction per user action.
- No amount, spending or category name reaches Logcat. Every new model, entity, state and draft that holds an amount overrides `toString()` without it.
- Every amount on screen is its own `MoneyText`. No `Color(...)` or `.dp` outside `ui/common/theme/`. No Material FAB, `Slider` or `LinearProgressIndicator` in feature code.
- Copy in `vi` (default), `en`, `ja`, `zh-rCN`. Fixed `vi` copy from the spec: "Tổng ngân sách", "Đã chi", "Còn", "Vượt", "Hết", "Sắp hết", "/ngày", "Gồm kết chuyển", "%1$s đã dùng %2$d%% ngân sách tháng", channel "Ngân sách".
- House rules the build enforces: a `Boolean` property starts with `is|has|should` (`NamingKonsistTest`); a feature root holds only `*Contract`, `*ViewModel`, `*Screen` files, dialogs and sheets live in `component/`, and screens and components never call `startActivity` (`FeatureTemplateKonsistTest`); no `@SuppressLint` (`ProjectRulesKonsistTest`); at most 6 function or constructor parameters (detekt `LongParameterList`, runs in `qualityGate`, not pre-commit).
- Limit cap: `BudgetRules.MAX_LIMIT = 9_999_999_999_999L` (13 digits, same as `AmountExpression.MAX_DIGITS`). Threshold choices: `50, 70, 80, 90`, default `80`. Full mark: `100`.
- Run Gradle through the `gradle-run` skill (`'.\gradlew.bat'` from Bash): `testDebugUnitTest` after each logic task; UI tasks also run `updateDebugScreenshotTestDefaultTestSuite` and look at the PNGs; `qualityGate` at the end.

## Review Focus

1. The process lives past midnight at month end (listener keeps it alive): the next check must copy the new month and alert on it, not on the old one → test in Task 7.
2. A burst of writes (pairing writes two rows and a transfer) triggers several checks: one alert, never two → test in Task 7.
3. Delete category A into B when B already has a budget in some months and not in others: no unique-index crash, B's own budget wins → test in Task 4.
4. Refunds make spent negative; a negative carry makes available ≤ 0 with no spending: no crash, no alert, "Hết" shown → tests in Task 2.
5. A month the user never opened sits between two set-up months: the chain carries through it and its spending counts → test in Task 3.
